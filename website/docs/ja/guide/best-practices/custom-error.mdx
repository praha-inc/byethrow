# カスタムエラー

`Result` のエラーにはどんな値でも使えますが、単なる文字列や汎用的な `Error` オブジェクトでは、呼び出し側が失敗の種類を区別しにくくなります。
失敗の種類ごとに専用のエラー型を用意することを強く推奨します。
このページでは、その選択肢と、カスタムエラーを効率よく作成する方法を説明します。

## カスタムエラーを定義する 2 つの方法

### 1. エラークラス（推奨）

組み込みの `Error` クラスを継承したクラスを定義し、一意な `name` を付けます。

```ts
import { Result } from '@praha/byethrow';
import { z } from 'zod';

class ValidationError extends Error {
  override readonly name = 'ValidationError';
}

const validateEmail = (email: string): Result.Result<string, ValidationError> => {
  return Result.pipe(
    email,
    Result.parse(z.email()),
    Result.mapError((issues) => new ValidationError('Invalid email format', { cause: issues })),
  );
};
```

### 2. タグ付きオブジェクト

エラーの種類を識別するプロパティを持つプレーンオブジェクトを使うこともできます。

```ts
import { Result } from '@praha/byethrow';
import { z } from 'zod';

type ValidationError = {
  type: 'ValidationError';
  message: string;
  value: string;
};

const validateEmail = (email: string): Result.Result<string, ValidationError> => {
  return Result.pipe(
    email,
    Result.parse(z.email()),
    Result.mapError(() => ({
      type: 'ValidationError',
      message: 'Invalid email format',
      value: email,
    })),
  );
};
```

## エラークラスを推奨する理由

どちらの方法でも呼び出し側はエラーを区別できますが、エラークラスには実用上の利点がいくつかあります。

### スタックトレースとエラーチェーン

`Error` は作成された場所を示すスタックトレースを記録し、`cause` オプションはその原因となった元のエラーを保持します。
この 2 つを組み合わせることで、デバッグがずっと簡単になります。

```ts
type User = { id: string; name: string };
declare const database: { findUser: (id: string) => Promise<User> };
// ---cut-before---
import { Result } from '@praha/byethrow';

class DatabaseError extends Error {
  override readonly name = 'DatabaseError';
}

const fetchUser = (id: string) => Result.try({
  try: () => database.findUser(id),
  // スタックトレースはここを指し、元のエラーは `cause` として保持される
  catch: (error) => new DatabaseError('Failed to fetch user', { cause: error }),
});
```

### `throw` との互換性

`Result` のエラーは、アプリケーションの境界で [`unwrap`](../tutorial/resolving/unwrapping) を使ったときなど、最終的に throw されることがあります。
エラー監視ツールやランタイムは、throw される値が `Error` のインスタンスであることを前提としています。プレーンオブジェクトを throw するとスタックトレースがなく、うまく報告されないことがよくあります。

## 推奨：`@praha/error-factory` を使う

エラークラスを手書きしていると、すぐに同じようなコードの繰り返しになります。
[`@praha/error-factory`](https://github.com/praha-inc/error-factory) を使うと、定型的なコードを減らし、エラーの構造を一貫させることができます。

### エラーを定義する

`ErrorFactory` が返すクラスを継承します。
`name` はリテラル型になるため、TypeScript はエラーのユニオン型を `name` によって絞り込めます。

```ts
import { ErrorFactory } from '@praha/error-factory';

class ValidationError extends ErrorFactory({
  name: 'ValidationError',
  message: 'Invalid input provided',
}) {}

class QueryError extends ErrorFactory({
  name: 'QueryError',
  message: 'An error occurred while executing a query',
  // エラーが持つ追加のフィールド
  fields: ErrorFactory.fields<{ query: string }>(),
}) {}

class NotFoundError extends ErrorFactory({
  name: 'NotFoundError',
  message: 'Resource not found',
}) {}
```

`message` には、フィールドからメッセージを組み立てる関数を指定することもできます。

```ts
import { ErrorFactory } from '@praha/error-factory';

class HttpError extends ErrorFactory({
  name: 'HttpError',
  message: ({ status }) => `Request failed with status ${status}`,
  fields: ErrorFactory.fields<{ status: number }>(),
}) {}
```

### Result の中でエラーを使う

失敗が発生した場所でエラーを作成し、元のエラーを `cause` として渡したうえで、必要なフィールドを埋めます。

```ts
import { ErrorFactory } from '@praha/error-factory';

class ValidationError extends ErrorFactory({
  name: 'ValidationError',
  message: 'Invalid input provided',
}) {}

class QueryError extends ErrorFactory({
  name: 'QueryError',
  message: 'An error occurred while executing a query',
  fields: ErrorFactory.fields<{ query: string }>(),
}) {}

class NotFoundError extends ErrorFactory({
  name: 'NotFoundError',
  message: 'Resource not found',
}) {}

type UserRow = { id: string; name: string };
declare const database: { query: (sql: string, params: unknown[]) => Promise<UserRow | undefined> };
// ---cut-before---
import { Result } from '@praha/byethrow';
import { z } from 'zod';

const validateId = (id: string) => {
  return Result.pipe(
    id,
    Result.parse(z.string().startsWith('u')),
    Result.mapError((issues) => new ValidationError({ cause: issues })),
  );
};

const executeQuery = (sql: string, params: unknown[]) => {
  return Result.try({
    try: () => database.query(sql, params),
    catch: (error) => new QueryError({ query: sql, cause: error }),
  });
};

const findUser = (id: string) => {
  return Result.pipe(
    validateId(id),
    Result.andThen((id) => executeQuery('SELECT * FROM users WHERE id = ?', [id])),
    Result.andThen((row) => {
      if (!row) {
        return Result.fail(new NotFoundError());
      }
      return Result.succeed({ id: row.id, name: row.name });
    }),
  );
};
// 型: (id: string) => Result.ResultAsync<{ id: string; name: string }, ValidationError | QueryError | NotFoundError>
```

### エラーを処理する

各エラーはリテラル型の `name` を持つため、`switch` 文によってエラーをフィールドも含めた正確なクラスに絞り込めます。

```ts
import { Result } from '@praha/byethrow';
import { ErrorFactory } from '@praha/error-factory';

class ValidationError extends ErrorFactory({
  name: 'ValidationError',
  message: 'Invalid input provided',
}) {}

class QueryError extends ErrorFactory({
  name: 'QueryError',
  message: 'An error occurred while executing a query',
  fields: ErrorFactory.fields<{ query: string }>(),
}) {}

class NotFoundError extends ErrorFactory({
  name: 'NotFoundError',
  message: 'Resource not found',
}) {}

declare const findUser: (id: string) => Result.ResultAsync<{ id: string; name: string }, ValidationError | QueryError | NotFoundError>;
// ---cut-before---
const result = await findUser('u123');

if (Result.isSuccess(result)) {
  console.log(result.value);
} else {
  switch (result.error.name) {
    case 'ValidationError':
      console.error('Validation error:', result.error.message);
      break;
    case 'QueryError':
      // QueryError に絞り込まれているので `query` にアクセスできる
      console.error('Query error:', result.error.message, 'Query:', result.error.query);
      break;
    case 'NotFoundError':
      console.error('Not found error:', result.error.message);
      break;
  }
}
```

網羅性チェックを含む、エラーのユニオン型を処理するその他の方法については、[パターンマッチング](./pattern-matching)を参照してください。
