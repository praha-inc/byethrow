# パターンマッチング

`Result` のエラー型は、処理が失敗しうるパターンごとに 1 つずつ、ユニオン型になっていることがよくあります。
このページでは、エラー型ごとに適切に処理する方法と、処理漏れを防ぐ方法を紹介します。

## 例

このページの例では、投稿を削除する関数を使います。この関数は 3 通りの理由で失敗する可能性があります。
[カスタムエラー](./custom-error)で推奨しているとおり、各エラーは一意な `name` を持つクラスです。

```ts
// @noErrors
import { ErrorFactory } from '@praha/error-factory';
import { Result } from '@praha/byethrow';

class PostNotFoundError extends ErrorFactory({
  name: 'PostNotFoundError',
  message: 'The requested post was not found.',
}) {}

class PostPermissionError extends ErrorFactory({
  name: 'PostPermissionError',
  message: 'You do not have permission to perform this action.',
}) {}

class PostAlreadyDeletedError extends ErrorFactory({
  name: 'PostAlreadyDeletedError',
  message: 'This post has already been deleted.',
}) {}

type PostDeleteError = (
  | PostNotFoundError
  | PostPermissionError
  | PostAlreadyDeletedError
);

const deletePost = async (postId: string): Result.ResultAsync<void, PostDeleteError> => {
  // 失敗時には上記のいずれかのエラーを返す
};
```

## 推奨：`ts-pattern` を使う

パターンマッチングには [`ts-pattern`](https://github.com/gvergnaud/ts-pattern) をおすすめします。
TypeScript のサポートが優れており、処理されていないエラー型があれば `.exhaustive()` がコンパイルエラーを報告します。

### エラーをマッチングする

```ts
// @filename: delete-post.ts
import { ErrorFactory } from '@praha/error-factory';
import { Result } from '@praha/byethrow';

export class PostNotFoundError extends ErrorFactory({
  name: 'PostNotFoundError',
  message: 'The requested post was not found.',
}) {}

export class PostPermissionError extends ErrorFactory({
  name: 'PostPermissionError',
  message: 'You do not have permission to perform this action.',
}) {}

export class PostAlreadyDeletedError extends ErrorFactory({
  name: 'PostAlreadyDeletedError',
  message: 'This post has already been deleted.',
}) {}

export type PostDeleteError = (
  | PostNotFoundError
  | PostPermissionError
  | PostAlreadyDeletedError
);

export const deletePost = async (postId: string): Result.ResultAsync<void, PostDeleteError> => {
  return Result.succeed();
};

// @filename: index.ts
import { deletePost } from './delete-post';
// ---cut-before---
import { Result } from '@praha/byethrow';
import { match } from 'ts-pattern';

await Result.pipe(
  deletePost('123'),
  Result.inspectError((error) => {
    match(error)
      .with({ name: 'PostNotFoundError' }, () => {
        console.error('The requested post was not found.');
      })
      .with({ name: 'PostPermissionError' }, () => {
        console.error('You do not have permission to perform this action.');
      })
      .with({ name: 'PostAlreadyDeletedError' }, () => {
        console.error('This post has already been deleted.');
      })
      .exhaustive(); // 処理漏れがあるとコンパイルエラーになる
  }),
);
```

## 代替案：TypeScript の標準機能

依存関係を増やしたくない場合は、TypeScript の組み込み機能でも同じことができます。

### `switch` 文を使う

各エラーはリテラル型の `name` を持つため、`switch` 文の各 `case` でエラーの型が絞り込まれます。
`default` で `satisfies never` を書いておくと、`ts-pattern` と同じ網羅性チェックが得られます。

```ts
// @filename: delete-post.ts
import { ErrorFactory } from '@praha/error-factory';
import { Result } from '@praha/byethrow';

export class PostNotFoundError extends ErrorFactory({
  name: 'PostNotFoundError',
  message: 'The requested post was not found.',
}) {}

export class PostPermissionError extends ErrorFactory({
  name: 'PostPermissionError',
  message: 'You do not have permission to perform this action.',
}) {}

export class PostAlreadyDeletedError extends ErrorFactory({
  name: 'PostAlreadyDeletedError',
  message: 'This post has already been deleted.',
}) {}

export type PostDeleteError = (
  | PostNotFoundError
  | PostPermissionError
  | PostAlreadyDeletedError
);

export const deletePost = async (postId: string): Result.ResultAsync<void, PostDeleteError> => {
  return Result.succeed();
};

// @filename: index.ts
import { deletePost } from './delete-post';
// ---cut-before---
import { Result } from '@praha/byethrow';

await Result.pipe(
  deletePost('123'),
  Result.inspectError((error) => {
    switch (error.name) {
      case 'PostNotFoundError':
        console.error('The requested post was not found.');
        break;
      case 'PostPermissionError':
        console.error('You do not have permission to perform this action.');
        break;
      case 'PostAlreadyDeletedError':
        console.error('This post has already been deleted.');
        break;
      default:
        // 処理漏れがあるとコンパイルエラーになる
        error satisfies never;
    }
  }),
);
```

### `instanceof` を使う

`instanceof` による判定でもエラーの型を絞り込めます。
ただし網羅性チェックは行われないため、新しく追加されたエラー型に気づかない可能性がある点に注意してください。

```ts
// @filename: delete-post.ts
import { ErrorFactory } from '@praha/error-factory';
import { Result } from '@praha/byethrow';

export class PostNotFoundError extends ErrorFactory({
  name: 'PostNotFoundError',
  message: 'The requested post was not found.',
}) {}

export class PostPermissionError extends ErrorFactory({
  name: 'PostPermissionError',
  message: 'You do not have permission to perform this action.',
}) {}

export class PostAlreadyDeletedError extends ErrorFactory({
  name: 'PostAlreadyDeletedError',
  message: 'This post has already been deleted.',
}) {}

export type PostDeleteError = (
  | PostNotFoundError
  | PostPermissionError
  | PostAlreadyDeletedError
);

export const deletePost = async (postId: string): Result.ResultAsync<void, PostDeleteError> => {
  return Result.succeed();
};

// @filename: index.ts
import { deletePost, PostNotFoundError, PostPermissionError, PostAlreadyDeletedError } from './delete-post';
// ---cut-before---
import { Result } from '@praha/byethrow';

await Result.pipe(
  deletePost('123'),
  Result.inspectError((error) => {
    if (error instanceof PostNotFoundError) {
      console.error('The requested post was not found.');
    }
    if (error instanceof PostPermissionError) {
      console.error('You do not have permission to perform this action.');
    }
    if (error instanceof PostAlreadyDeletedError) {
      console.error('This post has already been deleted.');
    }
  }),
);
```

## どこでマッチングするか

上の例では `inspectError` を使い、エラーごとに副作用を実行しています。
同じテクニックは、エラーを受け取るどの関数でも使えます。

- [`inspectError`](../tutorial/chaining/debugging)：ログ出力やメッセージの表示などの副作用を実行する。
- [`mapError`](../tutorial/chaining/mapping-results)：HTTP レスポンスなど、各エラーを別の値に変換する。
- [`orElse`](../tutorial/chaining/chaining-results)：一部のエラーから回復し、それ以外はそのまま後続に渡す。
